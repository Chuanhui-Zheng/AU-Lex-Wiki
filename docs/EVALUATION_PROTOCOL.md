# Retrieval evaluation protocol

The resume metrics are generated by `scripts/evaluate_rag.py`; they are not
hand-entered.

1. Freeze a JSON question set with one expected source title and optional
   section/term checks.
2. Run the original simple PostgreSQL `plainto_tsquery` baseline.
3. Run the optimized text-only retriever with title-aware scoping and the
   workplace-law domain gate.
4. Count a source hit when the expected document appears in the first five
   results; calculate MRR from the first matching rank.
5. Calculate evidence-term coverage over the first five result bodies.
6. Run the same questions through offline Ask and compare its refusal flag with
   the `in_scope` label.
7. Record median and P95 local retrieval latency for the optimized pass.

This protocol measures retrieval and refusal safeguards. It does not claim
RAGAS Faithfulness, Answer Correctness, or production throughput. Those need a
fixed generated-answer set, a fixed judge model, and a deployment benchmark.

The V4 run is reproduced with:

```bash
python -m scripts.evaluate_rag \
  --questions config/eval_questions_v4.json \
  --report docs/RAG_EVALUATION_V4.md \
  --json-report output/rag_evaluation_v4.json
```
